# Pod 调度需求分析（基于拓扑感知调度）

> 本文基于 `network_dispatch.excalidraw.svg` 中描述的拓扑调度场景，将 Pod 调度过程中可能出现的硬性调度需求映射到现有 NGD/NGG 双 CRD 设计。

---

## 1. 硬性调度需求（Filter 层 -- 不满足则调度失败）

| 编号 | 需求 | 说明 | 对应 NGD 字段 | 对应 NGG 字段 |
|---|---|---|---|---|
| H1 | 同汇聚层约束 | Pod 必须调度到同一汇聚交换机下的主机，避免跨防火墙导致性能下降 | `nodeSelector.matchLabels`（拓扑标签：汇聚层标识） | `nodes[].name`（PRC 筛选后仅含同汇聚层节点） |
| H2 | 同接入层约束 | Pod 必须调度到同一接入交换机下的主机，保证高性能网络（要求同接入则隐含同汇聚） | `nodeSelector.matchLabels`（拓扑标签：接入层标识） | `nodes[].name`（PRC 筛选后仅含同接入层节点） |
| H3 | 吞吐量约束 | 主机吞吐量需满足最低要求（按 5 分钟平均水平计算） | 需扩展：新增 `minThroughput` 字段 | `nodes[].resources` 扩展吞吐量指标 |
| H4 | 子网网段约束 | Pod 必须调度到指定子网网段的主机上 | `nodeSelector.matchLabels`（子网标签） | `nodes[].name`（PRC 按子网筛选） |
| H5 | 跨集群互访 IP 亲和 | 与指定其他集群 IP 列表同汇聚层（可选强制），IP 列表分属多个汇聚层则需求无效 | 需扩展：新增 `crossClusterAffinity.ipList` + `crossClusterAffinity.enforce` 字段 | 需扩展：节点拓扑信息（汇聚层归属） |
| H6 | 本集群互访 IP 亲和 | 与指定本集群 IP 列表强制同汇聚层，用于扩容场景 | 需扩展：新增 `intraClusterAffinity.ipList` 字段 | 需扩展：节点拓扑信息（汇聚层归属） |
| H7 | 同机房约束 | Pod 必须调度到同一机房内的主机，确保物理位置集中，跨机房网络延迟和运维成本显著增加 | `nodeSelector.matchLabels`（拓扑标签：机房标识） | `nodes[].name`（PRC 筛选后仅含同机房节点） |
| H8 | 最小资源保障 | 节点组的总可用资源（CPU/内存）须满足作业声明的最小资源需求，不足则该节点组不可用 | 需扩展：新增 `minResources` 字段 | 不涉及（PRC 校验候选集总资源，不足则 NGD status.phase=Failed） |
| H9 | 外部网络互通 | Pod 所在节点必须能与外部存储集群（OZONE、Shuffle）网络互通，确保数据读写通道畅通 | 需扩展：新增 `networkReachability.targets` 字段 | 需扩展：节点网络可达性标注（`nodes[].topology.networkReachable`） |

## 2. 软性调度需求（Score 层 -- 用于优选排序）

> 以下需求影响节点打分排序，**不必须在 CRD 中体现**，主要由 PRC 内部打分逻辑或 Volcano 插件 ScoreFn 实现。NGG 的 `nodes[].score` 和 `nodes[].resources` 字段可携带相关数据供打分使用，但软性需求本身不作为 Filter 拦截条件。

| 编号 | 需求 | 说明 | 实现方 |
|---|---|---|---|
| S1 | 主机负载感知 | CPU 使用率、内存使用率低的节点优先 | PRC 打分 -> NGG `score` |
| S2 | 网络设备负载感知 | 汇聚/接入交换机的 CPU、内存、端口包转发率负载低的优先 | PRC 打分 -> NGG `score` 加权 |
| S3 | 端口带宽感知 | 端口上行/下行宽带使用率低的优先 | PRC 打分 -> NGG `resources` 辅助 |
| S4 | 连接数感知 | 并发连接数少、新建会话速率低的优先 | PRC 打分 -> NGG `resources` 辅助 |
| S5 | 网络跳数最小化 | 中间件进程间互访跳数少的优先 | PRC 打分 -> NGG `topology.hops` 辅助 |
| S6 | 子网一致性偏好 | 尽量和互访方在同一子网 | PRC 打分（软性偏好，区别于 H4 硬性约束） |
| S7 | 机架亲和偏好 | 优先将 Pod 调度到同一机架或相邻机架的节点，减少跨机架网络跳数和布线成本 | PRC 打分 -> NGG `score` 加权（基于机架归属计算） |

## 3. 拓扑层级模型

```
机房（数据中心）
  └─ PE路由器
       └─ 楼核心交换机/路由器
            └─ 汇聚交换机        ← 跨汇聚层会经过防火墙，性能下降
                 └─ 接入交换机   ← 同汇聚不同接入，网络性能一致
                      └─ 机架    ← 同机架节点网络距离最近
                           └─ 主机
                                └─ 中间件进程
```

**关键拓扑规则：**

| 规则 | 说明 |
|---|---|
| 跨机房性能差异 | 跨机房必然跨汇聚层，网络延迟和防火墙开销显著，且可能涉及跨机房专线 |
| 跨汇聚层性能差异 | A->B（同汇聚）与 A->D（跨汇聚）性能完全不一致，跨汇聚有防火墙 |
| 同汇聚性能一致 | A->B 与 A->C（同汇聚不同接入）网络性能一样 |
| 同机架性能最优 | 同机架节点共享接入交换机，网络跳数最少，性能最优 |
| 网关决定汇聚层 | 不同网关的主机一定在不同汇聚层下 |
| IP 反查拓扑 | 通过 IP 可反查所属机房、汇聚层、接入层和机架 |

## 4. 集群创建场景需求

创建集群时（如 3 master + 3 node），所有节点应尽量满足：

| 优先级 | 需求 | 性质 |
|---|---|---|
| P0 | 同一机房、同一子网 | 硬性 |
| P0 | 满足最小资源需求（CPU/内存） | 硬性 |
| P0 | 与 OZONE/Shuffle 存储集群网络互通 | 硬性 |
| P1 | 所在交换机 CPU/内存可用多、带宽可用多 | 软性 |
| P2 | 同一接入层、同一汇聚层 | 软性 |
| P3 | 机架尽可能靠近 | 软性 |
| P4 | 与互访方跳数少 | 软性 |

## 5. NGD / NGG 扩展设计表

### 5.1 NGD spec 扩展字段

| 字段路径 | 类型 | 说明 | 对应需求 |
|---|---|---|---|
| `spec.minThroughput` | string | 最低吞吐量要求（按 5 分钟平均水平计算），不满足的节点被过滤 | H3 |
| `spec.crossClusterAffinity.ipList` | string[] | 跨集群互访目标 IP 列表，PRC 据此反查汇聚层 | H5 |
| `spec.crossClusterAffinity.enforce` | boolean | 是否强制与互访实例同汇聚层，默认 false | H5 |
| `spec.intraClusterAffinity.ipList` | string[] | 本集群互访目标 IP 列表，强制同汇聚层，用于扩容场景 | H6 |
| `spec.minResources` | object | 节点组最小资源保障（CPU/内存），PRC 校验候选集总资源不满足则 NGD 状态置 Failed | H8 |
| `spec.networkReachability.targets` | string[] | 外部存储集群网络互通目标列表（如 `["ozone", "shuffle"]`），PRC 据此筛选网络可达的节点 | H9 |
| `spec.preferredSubnet` | string | 子网偏好（软性），优先调度到该子网的节点 | 集群创建 P0 |

### 5.2 NGG spec.nodes 扩展字段

> 拓扑字段用于信息展示和多 NGG 场景下的节点分组参考。打分输入数据（端口带宽、连接数、会话速率、交换机 CPU/内存等）由 PRC 内部读取并计算为最终 `score`，不暴露到 CRD。

| 字段路径 | 类型 | 说明 | 对应需求 |
|---|---|---|---|
| `spec.nodes[].topology.convergenceSwitch` | string | 汇聚交换机标识（IP 或名称） | H1, H5, H6 |
| `spec.nodes[].topology.accessSwitch` | string | 接入交换机标识（IP 或名称） | H2 |
| `spec.nodes[].topology.subnet` | string | 子网标识 | H4 |
| `spec.nodes[].topology.dataCenter` | string | 机房标识（数据中心名称或编号） | H7 |
| `spec.nodes[].topology.rack` | string | 机架标识 | S7 |
| `spec.nodes[].topology.hops` | integer | 网络跳数 | 集群创建 P4 |
| `spec.nodes[].topology.networkReachable` | string[] | 节点可到达的外部存储集群列表（如 `["ozone", "shuffle"]`） | H9 |
| `spec.nodes[].resources.throughput5mAvg` | string | 5 分钟平均吞吐量 | H3 |

### 5.3 NGG score 计算说明

> PRC 内部读取以下数据源计算 `nodes[].score`（0-100），计算过程不涉及 CRD，最终只将 score 写入 NGG。

| 打分维度 | 数据来源（PRC 内部） | 权重方向 |
|---|---|---|
| 主机 CPU/内存空闲度 | 负载数据快照（与 A-scheduler 同源） | 越高越优 |
| 交换机 CPU/内存负载 | 网络监控系统 | 越低越优 |
| 端口带宽利用率 | 网络监控系统（端口上行/下行宽带使用率） | 越低越优 |
| 并发连接数/新建会话速率 | 网络监控系统 | 越低越优 |
| 网络跳数 | 网络拓扑数据 | 越少越优 |
| 机架亲和度 | 网络拓扑数据（机架归属） | 同机架/相邻机架越优 |
